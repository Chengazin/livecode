# Безопасность паролей

## Хеширование с солью

### Что такое соль?

Соль (salt) — это случайная последовательность байтов, которая добавляется к паролю перед хешированием. Это делает хеши уникальными даже для одинаковых паролей, что затрудняет атаки с использованием радужных таблиц (rainbow tables).

### Реализация в проекте

Приложение использует **bcrypt** для хеширования паролей:

- **Алгоритм**: bcrypt (HMAC-based)
- **Раунды**: 12 (конфигурируется через `BCRYPT_ROUNDS` в `.env`)
- **Автоматическое добавление соли**: Да, каждый вызов `Hash::make()` генерирует новую соль

### Как это работает

```php
// В контроллере регистрации
$user = User::query()->create([
    'name' => $data['name'],
    'email' => $data['email'],
    'password_hash' => Hash::make($data['password']), // Автоматически добавляет соль
    'status' => 'active',
    'language' => $data['language'] ?? 'rus',
]);
```

### Структура bcrypt хеша

```
$2y$12$bVJ4A5wb8BTC44xe2pN1zOCrOS/u9pypThJYaqgyJpC.CDETyhdjW
         ^^
         Раунды (12 раундов)

$2y$12$bVJ4A5wb8BTC44xe2pN1z
               ^^^^^^^^^^^^^^^^
               Соль (22 символа в base64)
```

## Конфигурация

### Файл `config/hashing.php`

```php
'bcrypt' => [
    'rounds' => env('BCRYPT_ROUNDS', 12), // Количество раундов хеширования
    'verify' => true,                      // Проверка алгоритма при верификации
],
```

### Переменные окружения

```env
BCRYPT_ROUNDS=12  # В production используйте 12-14
```

## Тестирование

Для проверки безопасности хеширования паролей используйте тесты:

```bash
php artisan test tests/Feature/PasswordHashingSecurityTest.php
```

### Что тестируется

1. ✅ Пароли хешируются с bcrypt и солью
2. ✅ Одинаковые пароли дают разные хеши (благодаря уникальным солям)
3. ✅ Конфигурация bcrypt с достаточным количеством раундов
4. ✅ Bcrypt используется как алгоритм по умолчанию
5. ✅ Регистрация правильно хеширует пароли

## Безопасность при аутентификации

При входе используется `Hash::check()` для сравнения:

```php
if (! Hash::check($data['password'], $user->password_hash)) {
    return response()->json(['message' => 'Invalid credentials.'], 401);
}
```

Этот метод:
- ✅ Использует timing-safe сравнение для защиты от timing атак
- ✅ Поддерживает переверку хеша, если алгоритм изменился
- ✅ Автоматически обновляет хеш если нужны новые раунды

## Рекомендации

### Production среда

1. **BCRYPT_ROUNDS**: Используйте 12-14 для хорошего баланса между безопасностью и скоростью
   - 10-11: Быстро, но менее стойко
   - 12-13: Рекомендуется
   - 14-15: Очень безопасно, но медленно

2. **Мониторинг**: Включите логирование попыток регистрации/входа

3. **Rate Limiting**: Включен по умолчанию:
   - `/api/auth/register`: 10 запросов в минуту на IP
   - `/api/auth/login`: 20 запросов в минуту на IP (или 8 на email+IP комбинацию)
